# 知识索引技能

## 知识库结构

```
knowledge/
├── macro/                    # 宏观经济知识
│   ├── INDEX.md              #   所有知识条目的索引表
│   ├── SUMMARY.md            #   宏观知识系统性概括
│   ├── entries/              #   单条知识文件（md）
│   └── raw/                  #   原始资料存档（PDF, HTML 等）
│       └── INDEX.md          #     原始资料索引，关联到 entries/
├── industry/                 # 行业知识（结构同 macro）
│   ├── INDEX.md
│   ├── SUMMARY.md
│   ├── entries/
│   └── raw/
│       └── INDEX.md
└── company/                  # 公司知识（结构同 macro）
    ├── INDEX.md
    ├── SUMMARY.md
    ├── entries/
    └── raw/
        └── INDEX.md
```

核心原则：**每个知识条目都应有对应的原始资料支撑，每份原始资料都应可追溯到使用它的知识条目。**

## 来源可信度评估框架

在对任何来源进行总结前，必须先评估其可信度。评估从两个维度进行：

### 维度一：来源资质等级

| 等级 | 类别 | 示例 | 默认可信度 |
|------|------|------|-----------|
| L1 | 官方一手数据 | 央行公告、统计年鉴、SEC/港交所文件、公司审计年报 | 高 |
| L2 | 国际/权威机构 | IMF, World Bank, BIS, WTO | 高 |
| L3 | 顶级投行 | Goldman Sachs, Morgan Stanley, JPMorgan, UBS | 中高 |
| L4 | 国内头部券商 | 中金、中信、华泰、国泰君安 | 中 |
| L5 | 中小券商/研究机构 | 区域性券商、小型研究机构 | 中低（需交叉验证） |
| L6 | 财经媒体 | Bloomberg, Reuters, 财新, 华尔街见闻 | 视具体引用来源而定 |
| L7 | 自媒体/论坛 | 公众号、雪球、知乎、Reddit | 低（仅作参考线索，不作为知识依据） |

### 维度二：报告可信度因子

对每一份研报/分析报告，评估以下要素：

1. **数据可追溯性** — 报告中的数据是否标注了原始来源？能否追溯到一手数据？
2. **方法论透明性** — 分析框架和假设是否明确说明？
3. **利益冲突** — 来源方是否与被分析对象存在业务关系（如投行承销关系、券商持仓）？
4. **历史准确性** — 该来源过往判断的准确性如何？（可查历史研报对照实际走势）
5. **多源一致性** — 该信息的核心结论是否被其他独立来源验证？
6. **时效性** — 信息是否在有效期内？（宏观数据 < 3个月，行业/公司分析 < 6个月）

### 综合可信度标注

在知识条目的可信度字段使用以下标注：

```
可信度: 高   — L1-L2 来源 + 多源交叉验证一致
可信度: 中高 — L3 来源 + 数据可追溯 + 无明显利益冲突
可信度: 中   — L4 来源 + 部分因素存在不确定性
可信度: 中低 — L5 来源，或 L4 以上但存在方法/利益疑虑
可信度: 低   — L6-L7 来源，仅记录不依赖
可信度: 待验证 — 当前仅单一来源，尚需交叉验证
```

**关键原则**：
- 宁可标注"待验证"也不虚构确信度
- L5 及以下的来源不能独立支撑投资判断
- 单一来源的结论必须在 SUMMARY 中注明"需要进一步验证"

## 原始资料存档规范

### 需要存档的内容

- 公司年报/季报 PDF
- 券商/投行研报 PDF
- 官方统计数据文件
- 重要网页内容（WebFetch 结果以 `.md` 格式保存）
- 关键新闻/公告截图或文本

### 存档流程

1. **获取资料** — 通过 `WebFetch` 抓取内容，或下载可获取的 PDF
2. **文件命名** — `[YYYY-MM-DD]_[来源机构]_[标题].[扩展名]`
   - 示例：`2026-04-26_中金公司_2026年新能源汽车行业展望.pdf`
3. **保存文件** — 存放至对应层级的 `raw/` 目录
4. **记录索引** — 在 `raw/INDEX.md` 中添加条目行，填写"关联知识条目"列
5. **反向引用** — 在知识条目文件的"原始资料"节中引用 raw 文件路径

### 无法下载的文件

对于付费/受限的研报：
- 在 `raw/INDEX.md` 的"URL 存档"表中记录 URL 和访问日期
- 在知识条目中注明"仅基于公开摘要，未获取完整报告"

### raw/INDEX.md 更新

每次存档后，在对应层级的 `raw/INDEX.md` 中添加：

```
| 日期 | 来源机构 | 标题 | 文件名 | 关联知识条目 | 文件类型 |
```

## 新建知识条目

### 条目文件命名

`entries/YYYY-MM-DD_[简短主题描述].md`

### 条目文件模板

```markdown
# [主题标题]

**日期**: YYYY-MM-DD（知识获取日期）
**标签**: `标签1`, `标签2`, `标签3`
**来源**: [来源标题](URL)
**来源资质**: L1-L7
**可信度**: 高 / 中高 / 中 / 中低 / 低 / 待验证
**可信度评估说明**: （1-3 句说明为什么给出该可信度评级）

---

## 摘要

用 3-5 句话概括本条知识的核心内容。摘要中需区分"事实陈述"和"观点判断"。

## 要点

- 要点 1
- 要点 2
- ...

## 数据与指标

| 指标 | 数值 | 时间 | 数据来源 | 备注 |
|------|------|------|---------|------|
| ... | ... | ... | ... | ... |

## 对投资的影响

- 对宏观/行业/公司层面的具体影响
- 需要后续跟踪的要点

## 原始资料

- [存档文件](raw/YYYY-MM-DD_机构_标题.ext) — 如已存档
- [原始来源](URL)

## 信息来源

- [来源1](URL)
- [来源2](URL)
```

### 标签体系

**宏观标签**：`GDP`, `通胀`, `利率`, `货币政策`, `财政政策`, `就业`, `贸易`, `地缘政治`, `全球`, `中国`, `美国`, `欧洲`, `日本`, `新兴市场`

**行业标签**：根据具体行业添加，如 `新能源汽车`, `半导体`, `AI`, `消费电子`, `医药`, `金融`, `房地产` 等

**公司标签**：公司名称、股票代码

**通用标签**：`长期趋势`, `短期波动`, `风险提示`, `政策驱动`, `技术变革`

## 更新 INDEX.md

每次新建条目后，在对应层级 `INDEX.md` 的表格中添加一行：

- **macro**: `| 日期 | 主题 | 区域 | 可信度 | 文件 | 原始资料 | 标签 |`
- **industry**: `| 日期 | 行业 | 主题 | 区域 | 可信度 | 文件 | 原始资料 | 标签 |`
- **company**: `| 日期 | 公司 | 代码 | 行业 | 主题 | 可信度 | 文件 | 原始资料 | 标签 |`

条目按日期倒序排列（最新在最前）。

## 同步 SUMMARY.md

### 更新原则

1. SUMMARY.md 是对该层级所有知识的**系统性综合概括**，不是简单罗列条目
2. 每次新增/更新知识条目后，检查 SUMMARY.md 是否还能准确反映当前知识全貌
3. 更新时修改 `**最后更新**:` 日期
4. **在总结中对每个重要判断标注其可信度水平**，若基于低可信度来源则明确提示

### 编写要求

- **macro/SUMMARY.md**：概括当前宏观经济全貌 — 增长、通胀、货币/财政政策方向、主要风险
- **industry/SUMMARY.md**：概括各行业格局 — 景气度排序、共有趋势、政策影响、投资主线
- **company/SUMMARY.md**：概括跟踪公司的情况 — 共同主题、业绩分化、估值水平、关注要点

### 总结撰写要点

- 从所有现有条目中提炼，而非仅依赖最新一篇
- 明确指出目前的**共识**和**分歧点**
- 区分 **"确定性高的判断"**（多源 L1-L3 交叉验证）和 **"需要进一步验证的假设"**（单一来源或 L5 以下）
- 标注**信息缺口** — 哪些关键问题目前缺乏数据支撑
- 涉及具体数据的判断，引用其原始来源和可信度等级

## 知识清理

定期检查知识库：
- 超过 6 个月的宏观数据条目应标记 `[数据可能过时]`
- 超过 12 个月的知识条目应标记 `[待复核]`
- 已被证伪或过时的信息应标记 `[已过时]` 并在 SUMMARY.md 中移除
- 删除明显错误的条目（保留删除记录在 git 历史中）
- 低可信度（中低及以下）且长期无交叉验证的条目应重新评估或降级
