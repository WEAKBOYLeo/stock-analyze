# 任务管理技能

## 核心定位

本技能管理的是**项目级大任务** — 调研方向、系统建设、知识库维护等跨会话的持久化任务。

**与对话级任务的区别**：
- 项目级任务（TASKS.md）："完成新能源汽车行业全景调研" — 跨多天/多会话
- 对话级任务（TaskCreate）："搜索蔚来2025年报" — 当前会话内的步骤

## 任务文件

`TASKS.md` — 项目根目录下的持久化任务文件，在所有会话间共享。

### 任务分类

| 分类 | 前缀 | 说明 |
|------|------|------|
| 宏观经济跟踪 | M-XXX | 宏观指标监控、央行政策跟踪等 |
| 行业研究 | I-XXX | 行业全景调研、赛道分析等 |
| 公司深度调研 | C-XXX | 单家公司深度分析、对比研究等 |
| 知识库维护 | K-XXX | 数据更新、信息复核、清理等 |
| 项目系统建设 | S-XXX | 架构优化、技能改进、工具配置等 |

### 任务条目模板

```markdown
### [编号] 任务标题
**状态**: 📋/🔄/✅/⏸️/❌ | **优先级**: P0-P3 | **创建**: YYYY-MM-DD | **目标完成**: YYYY-MM-DD（可选）

**描述**: 一句话说明任务目标和范围。

**依赖**: （可选）依赖的其他任务编号。

**子任务**:
- [ ] 子任务 1
- [x] 已完成子任务 2

**产出**: （完成时填写）关联的报告、知识条目等。
```

### 状态流转

```
📋 计划中 ──→ 🔄 进行中 ──→ ✅ 已完成
  │              │
  └──→ ❌ 取消   └──→ ⏸️ 暂停 ──→ 🔄 恢复
                      │
                      └──→ ❌ 取消
```

## 操作规范

### 创建任务

当用户提出新的调研方向或项目改进需求时：

1. 确定任务分类（M/I/C/K/S）
2. 分配下一个可用编号
3. 按模板创建任务条目，包含清晰的子任务分解
4. 若任务依赖其他未完成任务，在 `依赖` 字段中注明
5. 默认状态 `📋 计划中`，除非用户明确要求立即开始

**子任务拆分原则**：
- 每个子任务是可明确判断完成/未完成的独立单元
- 粒度适中：不大到需要多次会话才能完成，不小到单个搜索动作
- 示例：好的子任务 — "收集公司近三年财务数据并整理对比表"；不好的子任务 — "搜索财务数据"

### 更新状态

在以下时机更新 TASKS.md：

1. **开始调研** — 将任务状态改为 `🔄 进行中`
2. **完成调研** — 将任务状态改为 `✅ 已完成`，填写完成日期和产出列表
3. **遇到阻塞** — 将任务状态改为 `⏸️ 暂停`，注明阻塞原因
4. **放弃任务** — 将任务状态改为 `❌ 取消`，注明取消原因

### 产出关联

任务完成时，在 `产出` 节中链接：
- 调研报告：`reports/YYYY-MM-DD_*.md`
- 知识条目：`knowledge/[层级]/entries/YYYY-MM-DD_*.md`
- 原始资料：`knowledge/[层级]/raw/`

### 定期回顾

当用户开始新的调研会话时：
1. 读取 `TASKS.md` 了解当前任务全景
2. 提醒用户当前有哪些进行中和计划中的任务
3. 确认本次会话的优先级

### 任务归档

- 已完成超过 30 天的任务移入 `## 任务归档` 区
- 归档时保留完整的子任务和产出记录
- 取消的任务直接标记为 `❌`，不归档

## TASKS.md 文件约定

- 文件头部 `**最后更新**:` 日期在每次修改后更新
- 任务按分类组织在对应的章节下
- 同一分类内任务按编号排序
- 子任务使用 Markdown checkbox `- [ ]` / `- [x]`
- 任务编号唯一，永不重用
