# 知识索引技能

## 知识库结构

```
knowledge/
├── sources.yaml              # 来源可信度白名单（项目权威定义）
├── macro/                    # 宏观经济知识
│   ├── INDEX.md              #   知识条目索引（从 entries/entries.json 渲染生成）
│   ├── entries/              #   单条知识文件（md）
│   │   └── entries.json      #     程序化条目主索引（INDEX.md 从此渲染）
│   └── raw/                  #   原始资料存档（PDF, HTML 等）
│       ├── index.json         #     程序化原始资料索引
│       └── INDEX.md           #     人类可读补充索引
├── industry/                 # 行业知识（结构同 macro）
│   ├── INDEX.md
│   ├── entries/
│   │   └── entries.json
│   └── raw/
│       ├── index.json
│       └── INDEX.md
└── company/                  # 公司知识（结构同 macro）
    ├── INDEX.md
    ├── entries/
    │   └── entries.json
    └── raw/
        ├── index.json
        ├── INDEX.md
        └── {代码}-{公司名}/
```

核心原则：**每个知识条目都应有对应的原始资料支撑，每份原始资料都应可追溯到使用它的知识条目。**
索引层级：**entries.json → INDEX.md**（程序化主索引渲染人类可读索引），**raw/index.json + raw/INDEX.md**（原始资料双重索引）。

## 来源可信度评估框架

> **权威定义见 `knowledge/sources.yaml`** — 本文件所有 L1-L7 资质等级、采信规则、综合可信度标注标准均从 sources.yaml 引用。以下为该文件的概要，完整白名单请查阅 sources.yaml。

### 维度一：来源资质等级

sources.yaml 定义 7 个等级，含标签、默认可信度、具体来源列表。概要：

| 等级 | 类别 | 默认可信度 |
|------|------|-----------|
| L1 | 官方一手数据 | 高 |
| L2 | 国际/权威机构 | 高 |
| L3 | 顶级投行 | 中高 |
| L4 | 国内头部券商 | 中 |
| L5 | 中小券商/研究机构 | 中低（需交叉验证） |
| L6 | 财经媒体/数据平台 | 低 |
| L7 | 自媒体/论坛 | 低（仅作参考线索，不作为知识依据） |

### 维度二：报告可信度因子

对每一份研报/分析报告，评估以下要素：

1. **数据可追溯性** — 报告中的数据是否标注了原始来源？能否追溯到一手数据？
2. **方法论透明性** — 分析框架和假设是否明确说明？
3. **利益冲突** — 来源方是否与被分析对象存在业务关系（如投行承销关系、券商持仓）？
4. **历史准确性** — 该来源过往判断的准确性如何？（可查历史研报对照实际走势）
5. **多源一致性** — 该信息的核心结论是否被其他独立来源验证？
6. **时效性** — 信息是否在有效期内？（宏观数据 < 3个月，行业/公司分析 < 6个月）

### 综合可信度标注

根据 sources.yaml 中的 `credibility_labels` 定义：

```
可信度: 高   — L1-L2 来源 + 多源交叉验证一致
可信度: 中高 — L3 来源 + 数据可追溯 + 无明显利益冲突
可信度: 中   — L4 来源 + 部分因素存在不确定性
可信度: 中低 — L5 来源，或 L4 以上但存在方法/利益疑虑
可信度: 低   — L6-L7 来源，仅记录不依赖
可信度: 待验证 — 当前仅单一来源，尚需交叉验证
```

**关键原则**（来自 sources.yaml `rules`）：
- 宁可标注"待验证"也不虚构确信度
- L5 及以下的来源不能独立支撑投资判断
- 单一来源的结论必须在报告中注明"需要进一步验证"
- 多来源数据不一致时，优先采信 L1 官方数据，并记录分歧

## 原始资料存档规范

### 需要存档的内容

- 公司年报/季报 PDF
- 券商/投行研报 PDF
- 官方统计数据文件
- 重要网页内容（WebFetch 结果以 `.md` 格式保存）
- 关键新闻/公告截图或文本

### 存档流程

1. **获取资料** — 对于长文本高价值页面（研报全文、深度分析、官方长文），使用 `brave_llm_context` 获取 LLM 优化的清洁正文；对于需要保留原始格式的页面，使用 `WebFetch` 抓取
2. **文件命名** — 公司资料：`{代码}-{公司名}-{内容}.{扩展名}`；行业/宏观资料：`{日期}-{来源}-{主题}.{扩展名}`
   - 示例：`600169-太原重工-2025年报.pdf`、`2026-04-26_中金公司_新能源行业展望.pdf`
3. **目录结构** — 公司资料存放至 `raw/{代码}-{公司名}/` 子目录；行业/宏观直接放 `raw/`
4. **记录索引** — 更新 `raw/index.json`（程序化主索引）和 `raw/INDEX.md`（人类可读补充）
5. **反向引用** — 在知识条目文件的"原始资料"节中引用 raw 文件路径

### 无法下载的文件

对于付费/受限的研报：
- 在 `raw/INDEX.md` 的"URL 存档"表中记录 URL 和访问日期
- 在知识条目中注明"仅基于公开摘要，未获取完整报告"

### raw/INDEX.md 更新

每次存档后，在对应层级的 `raw/INDEX.md` 中添加：

```
| 日期 | 来源机构 | 标题 | 文件名 | 关联知识条目 | 文件类型 |
```

## 新建知识条目

### 条目文件命名

公司条目: `entries/{代码}-{公司名}-{主题}.md`（如 `600169-太原重工-15年财务数据.md`）
行业/宏观条目: `entries/YYYY-MM-DD_[简短主题描述].md`

### 条目文件模板

```markdown
# [主题标题]

**日期**: YYYY-MM-DD（知识获取日期）
**标签**: `标签1`, `标签2`, `标签3`
**来源**: [来源标题](URL)
**来源资质**: L1-L7
**可信度**: 高 / 中高 / 中 / 中低 / 低 / 待验证
**可信度评估说明**: （1-3 句说明为什么给出该可信度评级）

---

## 摘要

用 3-5 句话概括本条知识的核心内容。摘要中需区分"事实陈述"和"观点判断"。

## 要点

- 要点 1
- 要点 2
- ...

## 数据与指标

| 指标 | 数值 | 时间 | 数据来源 | 备注 |
|------|------|------|---------|------|
| ... | ... | ... | ... | ... |

## 对投资的影响

- 对宏观/行业/公司层面的具体影响
- 需要后续跟踪的要点

## 原始资料

- [存档文件](raw/YYYY-MM-DD_机构_标题.ext) — 如已存档
- [原始来源](URL)

## 信息来源

- [来源1](URL)
- [来源2](URL)
```

### 标签体系

**宏观标签**：`GDP`, `通胀`, `利率`, `货币政策`, `财政政策`, `就业`, `贸易`, `地缘政治`, `全球`, `中国`, `美国`, `欧洲`, `日本`, `新兴市场`

**行业标签**：根据具体行业添加，如 `新能源汽车`, `半导体`, `AI`, `消费电子`, `医药`, `金融`, `房地产` 等

**公司标签**：公司名称、股票代码

**通用标签**：`长期趋势`, `短期波动`, `风险提示`, `政策驱动`, `技术变革`

## 更新索引（entries.json → INDEX.md）

### 工作流

每次新建或更新条目后，修改 `entries/entries.json`，然后从中渲染生成 `INDEX.md`。

### entries.json 字段

条目按日期倒序排列（最新在最前）。

**macro 条目**：
```json
{
  "date": "YYYY-MM-DD",
  "topic": "主题标题",
  "region": "区域（如全球、中国、美国）",
  "credibility": "高/中高/中/中低/低/待验证",
  "file": "条目文件名.md",
  "raw_materials": ["原始资料路径1", "原始资料路径2"],
  "tags": ["标签1", "标签2"]
}
```

**industry 条目**：
```json
{
  "date": "YYYY-MM-DD",
  "industry": "行业名称",
  "topic": "主题标题",
  "region": "区域",
  "credibility": "高/中高/中/中低/低/待验证",
  "file": "条目文件名.md",
  "raw_materials": ["原始资料路径1"],
  "tags": ["标签1", "标签2"]
}
```

**company 条目**：
```json
{
  "date": "YYYY-MM-DD",
  "company": "公司名称",
  "code": "股票代码",
  "industry": "所属行业",
  "topic": "主题标题",
  "credibility": "高/中高/中/中低/低/待验证",
  "file": "条目文件名.md",
  "raw_materials": ["原始资料路径1"],
  "tags": ["标签1", "标签2"]
}
```

### INDEX.md 渲染

从 entries.json 渲染 INDEX.md 表格：

- **macro**: `| 日期 | 主题 | 区域 | 可信度 | 文件 | 原始资料 | 标签 |`
- **industry**: `| 日期 | 行业 | 主题 | 区域 | 可信度 | 文件 | 原始资料 | 标签 |`
- **company**: `| 日期 | 公司 | 代码 | 行业 | 主题 | 可信度 | 文件 | 原始资料 | 标签 |`

条目按日期倒序排列。INDEX.md 顶部已标注 `本文件由 entries/entries.json 自动生成，请勿手动编辑表格内容`。

## 搜索前校验 index.json（防重复搜集）

### 校验流程

在进行任何数据搜集或网络搜索之前，**必须**先校验知识库中是否已有相关数据：

1. **查 entries/entries.json** — 确认目标公司/行业/宏观主题是否已有知识条目
   - 查看条目的 `topic`、`date`、`raw_materials` 字段判断覆盖范围
2. **查 raw/index.json** — 确认原始资料（年报PDF、财务CSV等）的年份/范围覆盖
   - 查看 `files` 数组中的 `year`、`category` 字段
3. **对比需求与已有数据**：
   - **全部存在** → 跳过搜集，直接告知用户数据已就绪
   - **部分存在** → 只搜集缺失的年份/指标，已存在的跳过
   - **不存在** → 完整搜集

### 校验结果报告格式

```
## 数据就绪检查

| 层级 | 目标 | 已有数据 | 缺失数据 | 操作 |
|------|------|---------|---------|------|
| company | 600169 太原重工 | 2013-2025年报PDF + 2005-2026Q1财务CSV | 2010-2012年报PDF | 仅补足缺失年份 |
```

## 知识清理

定期检查知识库：
- 超过 6 个月的宏观数据条目应标记 `[数据可能过时]`
- 超过 12 个月的知识条目应标记 `[待复核]`
- 已被证伪或过时的信息应标记 `[已过时]` 并在 INDEX.md 中移除
- 删除明显错误的条目（保留删除记录在 git 历史中）
- 低可信度（中低及以下）且长期无交叉验证的条目应重新评估或降级
